초대 내역 삭제되지 않는 버그 분석

2025.01
Kotlin / Spring Boot / JPA / Validation

작업 기간

2025년 1월 2일 (1일)

현상

  • 동일한 계정이 "멤버"와 "초대 중인 멤버"에 동시에 표시됨
  • 이미 멤버인 사용자에게 불필요한 초대장이 생성됨

원인 분석

정상 흐름 vs 버그 흐름

단계 정상 흐름 버그 흐름
1 관리자가 초대 발송 관리자가 초대 발송
2 사용자가 초대 수락 → 멤버 등록 사용자가 초대 수락 → 멤버 등록
3 초대장 자동 삭제 관리자가 화면 새로고침 없이 "재발송" 클릭
4 - 새 초대장 생성 (검증 누락!)

버그 발생 시나리오

1. 관리자가 A씨에게 초대 발송 2. A씨가 초대 수락 → 멤버 등록됨, 초대장 삭제됨 3. 관리자 화면에는 여전히 초대장 표시 (새로고침 안 함) 4. 관리자가 "재발송" 클릭 → 이미 멤버인데 새 초대장 생성! 5. 결과: A씨가 멤버 + 초대 중 둘 다 표시 ← 버그

근본 원인: Validator 우회

호출 경로 검증 여부 이유
API 직접 호출 (POST /invitations) ✅ 검증됨 Controller에서 @Validated가 검증 실행
내부 메서드 호출 (renew() → invite()) ❌ 검증 안됨 Service 내부 호출은 Controller 검증 우회
내부 메서드 호출 (updateUserRole() → invite()) ❌ 검증 안됨 Service 내부 호출은 Controller 검증 우회

핵심 문제: renew()와 updateUserRole() 메서드가 내부적으로 invite()를 호출하면서 @ValidInvitation 검증을 우회함

해결책

수정 전 (버그)

관리자가 "재발송" 클릭 ↓ 기존 초대장 삭제 ↓ 새 초대장 바로 생성 ← 검증 없음! ↓ (이미 멤버여도 초대장 생성됨)

수정 후

관리자가 "재발송" 클릭 ↓ 기존 초대장 삭제 ↓ ★ 이미 멤버인지 확인 ★ ← 검증 추가! ↓ 멤버 아님 → 새 초대장 생성 멤버임 → 초대장 생성 안함 (에러 메시지)

구현

invite() 메서드 내부에 직접 검증 로직 추가:

  • ALREADY_BELONG_EMAIL: 이미 소속된 이메일인지 확인
  • ALREADY_INVITED_EMAIL: 이미 초대장이 있는 이메일인지 확인

결과: 테스트 코드로 버그 재현 후 수정, 더 이상 멤버와 초대장이 중복 생성되지 않습니다.

교훈

  • Controller 레벨의 @Validated는 Service 내부 호출에서 우회될 수 있습니다.
  • 비즈니스 로직의 핵심 검증은 Service 메서드 내부에도 구현해야 합니다.
  • 테스트 코드로 버그를 재현한 후 수정하면 회귀를 방지할 수 있습니다.
  • 프론트엔드 상태와 백엔드 상태의 불일치 상황을 고려해야 합니다.
