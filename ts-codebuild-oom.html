CodeBuild 타임아웃/OOM 해결

2025.10
AWS CodeBuild / Gradle / Kotlin / Swap Memory

작업 기간

2025년 10월 6일 ~ 20일 (약 2주)

현상

  • 백엔드 레포의 테스트 코드 양이 증가하면서 CodeBuild에서 OOM(Out of Memory) 또는 30분 Timeout 발생
  • CodeBuild 스펙: 2 vCPUs, 3.6GB Memory
  • 메모리 사용량 지표에서 3GB를 100% 사용 중
> Task :test FAILED FAILURE: Build failed with an exception. * What went wrong: Execution failed for task ':test'. > Process 'Gradle Test Executor 2' finished with non-zero exit value 137 # Exit code 137 = OOM Killed

시도한 해결책들

시도 1: @SpringBootTest → Mockk 변환 (실패)

  • 53개의 @SpringBootTest 중 21개를 일반 Mockk으로 변환
  • 로컬 테스트 결과: 75초 → 71초 (4초 개선)
  • 결과: 메모리 사용량 차이 없음, 여전히 137 Error 발생

시도 2: CodeBuild 로컬 캐시 (실패)

  • 캐시 적용 시 4분만에 빌드 완료
  • 문제점: 캐시 적용이 불규칙적, 실패해야 할 테스트가 성공할 수 있음
  • S3 캐시는 과금 문제로 사용 불가

시도 3: Swap Memory 설정 (성공)

물리적 메모리가 부족하면 가상 메모리(Swap)를 사용하도록 설정했습니다.

# buildspec.yml - echo "--- Configuring Swap (Virtual Memory) ---" - fallocate -l 8G /swapfile - chmod 600 /swapfile - mkswap /swapfile - swapon /swapfile - echo "--- Current Memory and Swap Status ---" - free -h - swapon -s
# 결과 total used free shared buff/cache available Mem: 3.6Gi 416Mi 1.5Gi 0.0Ki 1.8Gi 3.0Gi Swap: 8.0Gi 0B 8.0Gi ← 8G Swap 추가됨

해결책

최종 해결: 8GB Swap 메모리 설정으로 OOM과 30분 타임아웃 문제 해결. Storage 사용은 CodeBuild 과금 기준에 포함되지 않아 비용 문제 없음.

추가 개선사항

  • 테스트 프로필 수정: local → test (H2 memory DB 사용)
  • Gradle 병렬 실행 옵션 추가: -Dorg.gradle.parallel=true
  • 테스트 진척도 로그 추가: 50개 단위로 진행 상황 출력
테스트 진척도: 50개 완료 테스트 진척도: 100개 완료 ... 테스트 진척도: 750개 완료 테스트 진척도: 759개 완료

결과: is_deployable: false 기준 15분 빌드 시간 소요. 테스트 속도는 기존과 동일하지만 빌드 안정성이 크게 향상되었습니다.

교훈

  • 테스트 코드 최적화보다 인프라 설정(Swap)이 더 효과적인 경우가 있습니다.
  • CodeBuild의 Storage 사용은 과금되지 않으므로 Swap을 활용할 수 있습니다.
  • 빌드 진행 상황을 로그로 출력하면 디버깅과 모니터링에 도움이 됩니다.
  • Exit code 137은 Linux에서 OOM Killer에 의해 프로세스가 종료되었음을 의미합니다.
