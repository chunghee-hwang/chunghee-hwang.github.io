Prometheus Metric 데이터 유실 이슈

2025.12.26
Kubernetes / Prometheus / Terraform

작업 기간

2025년 12월 26일 (1일)

현상

  • Prometheus의 retention 설정은 15일로 되어있지만, 실제 Grafana에서 지표를 보면 2일치밖에 없거나 갑자기 사라지는 현상 발생
  • Pod가 재시작될 때마다 메트릭 데이터가 초기화됨

원인 분석

emptyDir 사용으로 인한 데이터 휘발

Prometheus 서버가 PersistentVolume(PV) 대신 emptyDir을 사용하고 있었습니다.

emptyDir이란?

Kubernetes에서 제공하는 임시 볼륨 타입 중 하나입니다.

항목 설명
생성 시점 Pod가 노드에 할당될 때 생성
초기 상태 이름 그대로 비어있음 (empty)
저장 위치 노드의 로컬 디스크 또는 메모리(tmpfs)
수명 Pod의 생명주기와 동일
삭제 시점 Pod가 노드에서 제거될 때 영구 삭제

데이터가 삭제되는 경우

상황 데이터 유지 여부
컨테이너 크래시/재시작 유지
Pod 재시작 (같은 노드) 삭제
Pod 재스케줄링 (다른 노드) 삭제
Deployment 업데이트 삭제
노드 재부팅 삭제

emptyDir vs PersistentVolume 비교

항목 emptyDir PersistentVolume
데이터 영속성 Pod 삭제 시 데이터 삭제 Pod 삭제 후에도 데이터 유지
적합한 용도 캐시, 임시 파일 데이터베이스, 메트릭 저장
스토리지 위치 노드 로컬 디스크 외부 스토리지 (Cinder 등)

Terraform 설정 확인

CSI Driver 문제로 인해 임시로 emptyDir을 사용하도록 설정되어 있었습니다.

# Persistence - CSI Driver 문제로 emptyDir 사용 "server.persistentVolume.enabled" = false, "server.emptyDir.sizeLimit" = local.prometheus_config.persistence_size,

실제 K8s 상태 확인

kubectl get deployment prometheus-server -n prometheus \ -o jsonpath='{.spec.template.spec.volumes}' # 결과: [ { "configMap": { "name": "prometheus-server" }, "name": "config-volume" }, { "emptyDir": { "sizeLimit": "8Gi" }, "name": "storage-volume" } ]

문제점: storage-volume이 emptyDir로 설정되어 있고, prometheus 네임스페이스에 PVC가 없었습니다.

해결책

1. PersistentVolume 사용하도록 Terraform 코드 수정

prod 환경:

# Persistence - PV 사용 "server.persistentVolume.enabled" = true, "server.persistentVolume.size" = local.prometheus_config.persistence_size, "server.persistentVolume.storageClass" = "csi-cinder-sc-retain-wffc",

dev 환경:

# Persistence - PV 사용 "server.persistentVolume.enabled" = true, "server.persistentVolume.size" = local.prometheus_config.persistence_size, "server.persistentVolume.storageClass" = "csi-cinder-sc-delete",

2. StorageClass 선택 기준

환경 StorageClass ReclaimPolicy 설명
prod csi-cinder-sc-retain-wffc Retain PVC 삭제 시에도 데이터 보존
dev csi-cinder-sc-delete Delete PVC 삭제 시 자동 정리

3. 적용 방법

cd prod/grafana terraform plan terraform apply

적용 후 Prometheus Pod가 재생성되며 PVC가 새로 생성됩니다. 이후부터는 Pod가 재시작되어도 메트릭 데이터가 유지됩니다.

결과: PersistentVolume 적용 후 Pod 재시작에도 메트릭 데이터가 정상적으로 유지되어 15일치 데이터를 확인할 수 있게 되었습니다.

참고: StorageClass 비교

VolumeBindingMode

StorageClass VolumeBindingMode 설명
csi-cinder-sc-retain Immediate PVC 생성 즉시 PV 생성
csi-cinder-sc-retain-wffc WaitForFirstConsumer Pod 스케줄링 시점에 PV 생성

ReclaimPolicy

ReclaimPolicy PVC 삭제 시 동작
Delete PV와 데이터 자동 삭제
Retain PV와 데이터 보존 (수동 정리 필요)

주의사항: 블록 스토리지는 특정 가용영역(AZ)에 바인딩됩니다. Pod가 다른 AZ의 노드로 이동하면 PV에 접근할 수 없으므로, 같은 AZ 내에서만 노드 간 이동이 가능합니다.

교훈

  • 메트릭, 로그 등 영구 보존이 필요한 데이터는 반드시 PersistentVolume을 사용해야 합니다.
  • emptyDir은 캐시, 임시 파일 등 휘발되어도 무방한 데이터에만 사용해야 합니다.
  • "임시" 설정이 운영 환경에 그대로 적용되지 않도록 코드 리뷰 시 주의가 필요합니다.
  • StorageClass 선택 시 환경별 ReclaimPolicy를 다르게 적용하면 운영 효율성을 높일 수 있습니다.
