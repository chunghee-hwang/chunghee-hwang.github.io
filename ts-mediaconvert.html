MediaConvert 인코딩 시 영상 길이 변경 문제

2025.10
AWS MediaConvert / FFprobe / Python

작업 기간

2025년 10월 (약 1주일 - 리서치 및 구현)

현상

  • AWS MediaConvert로 동영상 인코딩 시 원본과 결과물의 영상 길이가 달라지는 문제 발생
  • 소수점 차이로 정수 부분이 달라지면 (예: 9.99초 → 10초) 전송 서버에서 영상 길이 정보가 완전히 달라짐
  • DB에 영상 길이를 저장할 때 소수점을 버리고 있어서 문제가 발생

원인 분석

현재 인코딩 정책

원본 fps 처리 방식
24fps 미만 24fps로 강제 변환
24~60fps 원본 유지
60fps 초과 60fps로 강제 변환

문제 케이스: 프레임레이트 증가 (15fps → 24fps)

항목 원본 인코딩 후 차이
프레임레이트 15fps 24fps +9fps
비디오 프레임 수 101 프레임 162 프레임 +61 프레임
비디오 길이 6.733초 6.750초 +0.017초

원인: MediaConvert의 DUPLICATE_DROP 알고리즘은 정수 프레임만 처리 가능. 161.6 프레임 → 162 프레임으로 반올림되어 길이 증가.

운영 데이터 분석 결과

항목 개수 비율
총 인코딩 기록 454 100%
비디오 길이 변경 193 42.5%
프레임레이트 변경 → 길이 변경 188 97.4%

핵심: 비디오 길이 변경 193개 중 188개(97.4%)가 프레임레이트 강제 변환 때문

해결책

채택된 방안: 인코딩된 영상의 길이를 응답

기존에는 원본 영상 길이를 SDK에 응답했지만, 인코딩된 영상의 길이를 응답하도록 변경했습니다.

  • 고화질/중화질/저화질의 인코딩된 비디오 스트림 길이는 모두 일치
  • 100% 문제 해결 가능

도메인 변경사항

테이블 컬럼 설명
media_content_resources duration (BIGINT) 원본 비디오 길이 (기존 유지)
media_contents duration (REAL) - 신규 인코딩된 비디오 길이 (소수점 포함)

마이그레이션

-- 컬럼 추가 ALTER TABLE media_contents ADD duration REAL; -- 기존 데이터 마이그레이션 (인코딩된 영상 길이로 업데이트) UPDATE media_contents SET duration = mig.video_stream_length FROM mig_duration_to_media_contents mig WHERE mig.id = media_contents.id;

결과: SDK에 인코딩된 영상의 정확한 길이를 응답하여 영상 길이 불일치 문제가 100% 해결되었습니다.

교훈

  • 미디어 인코딩 시 프레임레이트 변환은 영상 길이에 영향을 줄 수 있습니다.
  • 운영 데이터를 분석하여 문제의 규모와 원인을 정확히 파악하는 것이 중요합니다.
  • 소수점 처리 방식(반올림, 버림)이 시스템 전체에 미치는 영향을 고려해야 합니다.
  • 원본 데이터와 가공 데이터를 분리하여 저장하면 유연성이 높아집니다.
