Airflow DAG 스케줄 시간 Drift 문제

2025.12
Airflow / PostgreSQL / NTP

작업 기간

2025년 12월 (약 2일 - 원인 분석 및 인프라팀 협업)

현상

  • Airflow DAG가 예정된 시간에 정확히 실행되지 않고, 실행 시간이 점점 밀리는 현상 발생
  • 예를 들어 매 정시에 실행되어야 하는 DAG가 00:00:18, 01:00:36, 02:00:54... 식으로 점점 늦어짐
  • 시간이 지날수록 drift가 누적되어 스케줄 예측이 어려워짐

원인 분석

1. Airflow 스케줄러의 시간 기준

Airflow 스케줄러는 메타데이터 DB(PostgreSQL)의 시간을 기준으로 DAG 실행 시점을 결정합니다. 스케줄러가 다음 실행 시점을 계산할 때 DB 서버의 now() 함수 결과를 참조합니다.

2. 시간 차이 확인

PostgreSQL 서버와 NTP 서버의 시간을 비교한 결과, PostgreSQL이 NTP 서버보다 약 18초 빠른 것으로 확인되었습니다.

# PostgreSQL 서버 시간 확인 SELECT now(); -- 결과: 2025-12-XX 00:00:18.XXX # NTP 서버 시간 (실제 표준 시간) -- 결과: 2025-12-XX 00:00:00.XXX # 차이: 약 18초

3. Drift 발생 메커니즘

문제가 발생하는 과정은 다음과 같습니다:

단계 설명
1 스케줄러가 "다음 실행 시간"을 계산 (DB 시간 기준)
2 DB 시간이 18초 빠르므로, 실제보다 18초 늦게 실행됨
3 다음 스케줄 계산 시 또 18초가 추가됨
4 시간이 지날수록 drift가 누적

근본 원인: 클라우드 PostgreSQL 인스턴스가 NTP 서버와 동기화되지 않아 시스템 시간이 점점 틀어진 상태였습니다.

해결책

1. 인프라팀에 NTP 동기화 요청

클라우드 PostgreSQL은 관리형 서비스로 직접 시스템 설정을 변경할 수 없어, 인프라팀(클라우드 제공업체)에 NTP 동기화 설정을 요청했습니다.

요청 내용: PostgreSQL 인스턴스의 시스템 시간을 NTP 서버와 동기화해주세요. 현재 약 18초의 시간 차이가 발생하여 Airflow 스케줄링에 문제가 있습니다.

2. 동기화 후 확인

인프라팀에서 NTP 동기화 설정 완료 후, 시간 차이가 해소되었는지 확인했습니다.

# 동기화 후 PostgreSQL 서버 시간 확인 SELECT now(); -- 결과: 2025-12-XX 00:00:00.XXX (NTP와 일치)

3. Airflow 스케줄 정상화 확인

NTP 동기화 후 DAG들이 예정된 시간에 정확히 실행되는 것을 확인했습니다.

# Airflow UI에서 DAG 실행 이력 확인 DAG: daily_report Scheduled: 2025-12-XX 00:00:00 Started: 2025-12-XX 00:00:01 # 정상 (1초 이내 시작)

결과: NTP 동기화 적용 후 DAG 스케줄이 정상화되어 예정된 시간에 정확히 실행되기 시작했습니다. Drift 현상이 완전히 해소되었습니다.

추가 고려사항

분산 시스템에서의 시간 동기화

분산 시스템에서는 여러 컴포넌트 간 시간 동기화가 매우 중요합니다:

  • 스케줄러 + DB: 이번 사례처럼 스케줄 drift 발생 가능
  • 로그 시스템: 시간이 맞지 않으면 로그 순서가 뒤섞여 디버깅이 어려워짐
  • 분산 트랜잭션: 시간 기반 충돌 해결 시 데이터 정합성 문제 발생 가능
  • 인증 토큰: 토큰 만료 시간 계산 오류로 인증 실패 가능

예방을 위한 모니터링

시간 동기화 문제를 조기에 발견하기 위한 모니터링 방안:

  • 주요 서버들의 시간 차이를 주기적으로 체크하는 스크립트 작성
  • NTP 동기화 상태를 모니터링하고 drift 발생 시 알림
  • Airflow DAG 실행 시간과 예정 시간의 차이를 메트릭으로 수집

교훈

  • 분산 시스템에서 시간 동기화는 기본 중의 기본이지만, 관리형 서비스에서는 간과하기 쉽습니다.
  • 스케줄 기반 작업에서 "점점 밀리는" 현상이 발생하면 DB 서버 시간을 의심해봐야 합니다.
  • 관리형 서비스라도 NTP 동기화 설정이 기본으로 되어있지 않을 수 있으므로 확인이 필요합니다.
  • 인프라팀과의 빠른 커뮤니케이션이 문제 해결 시간을 크게 단축시킵니다.
