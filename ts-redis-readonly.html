Redis Sentinel 장애조치 후 READONLY 쓰기 실패

2026.10
Redis Sentinel / Lettuce / Spring Data Redis / Kubernetes

현상

  • 개발계 Redis를 Sentinel 3노드로 전환한 뒤, 장애조치(failover)가 끝났는데도 일부 애플리케이션의 쓰기가 READONLY You can't write against a read only replica로 계속 실패
  • 송출 서버와 스트림 서버 2개, 총 3개 서비스에서 같은 증상

원인 분석

  • Redis 연결 팩토리에 readFrom이 설정돼 Lettuce가 MasterReplica 모드로 동작
  • 이 모드는 마스터 변경을 Sentinel 이벤트로만 반영하므로, 이벤트를 놓치면 강등된 옛 마스터(현재 replica)에 계속 쓰기를 보냄
  • Sentinel 주소도 headless 서비스 하나만 지정돼 있어, 해당 주소가 가리키는 Sentinel이 내려가면 다른 Sentinel로 넘어가지 못하는 구조

해결책

설정 변경

  • 연결 팩토리에서 readFrom 제거
  • Sentinel 주소를 headless 하나에서 파드별 3개로 변경
  • 설정이 의도대로 적용되는지 확인하는 컨텍스트 테스트 추가

결과:

  • 3개 서비스에 동일하게 적용해 장애조치 후 READONLY 쓰기 실패 문제 해소

교훈

  • Sentinel 전환은 서버 쪽 failover 시간만이 아니라 클라이언트가 새 마스터를 따라가는지까지 확인해야 끝난다.
  • 읽기 분산 옵션은 토폴로지 갱신 방식까지 바꿀 수 있으므로, 필요가 확실하지 않으면 켜지 않는다.
  • Sentinel 주소는 하나의 DNS 이름보다 노드별로 나열해 일부가 내려가도 조회할 수 있게 한다.
