ElasticSearch 트러블슈팅

2025.12.22
Kubernetes / ElasticSearch

작업 기간

2025년 12월 22일 (1일)

현상

ElasticSearch 클러스터에서 두 가지 문제가 동시에 발생했습니다:

  • ILM 정책 불일치: 인덱스에 적용된 ILM 정책이 실제 존재하지 않는 정책을 참조하고 있었음
  • APM 데이터스트림 미생성: APM 서버가 데이터를 수집하고 있지만 데이터스트림이 생성되지 않아 데이터가 저장되지 않음

원인 분석

1. ILM 정책 불일치 문제

조사 결과, 기존에 사용하던 ILM 정책이 삭제되었지만 해당 정책을 참조하는 인덱스들은 그대로 남아있었습니다. ElasticSearch는 인덱스가 존재하지 않는 정책을 참조할 경우 ILM 작업(롤오버, 삭제 등)을 수행하지 못합니다.

GET _ilm/policy/missing-policy-name // 결과: 404 Not Found - 정책이 존재하지 않음 GET index-name/_ilm/explain // 결과: policy "missing-policy-name" does not exist

2. APM 데이터스트림 미생성 문제

APM 관련 인덱스 템플릿이 존재하지 않거나 우선순위가 낮아 다른 템플릿에 의해 덮어씌워지고 있었습니다. 데이터스트림은 인덱스 템플릿이 반드시 존재해야 생성됩니다.

GET _index_template/apm-* // 결과: APM 관련 템플릿 누락 확인 GET _data_stream/traces-apm* // 결과: 데이터스트림 없음

해결책

1. ILM 정책 재생성

누락된 ILM 정책을 새로 생성하여 기존 인덱스들이 정상적으로 수명주기 관리를 받을 수 있도록 했습니다.

PUT _ilm/policy/logs-policy { "policy": { "phases": { "hot": { "min_age": "0ms", "actions": { "rollover": { "max_size": "50gb", "max_age": "1d" } } }, "delete": { "min_age": "7d", "actions": { "delete": {} } } } } }

2. APM 인덱스 템플릿 설정

APM 데이터용 인덱스 템플릿을 생성하고, 우선순위를 높게 설정하여 다른 템플릿과 충돌하지 않도록 했습니다.

PUT _index_template/apm-traces { "index_patterns": ["traces-apm*"], "data_stream": {}, "priority": 500, "template": { "settings": { "index.lifecycle.name": "apm-policy" } } }

3. 데이터스트림 생성 확인

템플릿 적용 후 APM 서버가 데이터를 전송하면 자동으로 데이터스트림이 생성됩니다.

GET _data_stream/traces-apm* // 결과: 데이터스트림 정상 생성 확인

결과: ILM 정책이 정상적으로 적용되어 인덱스 수명주기 관리가 재개되었고, APM 데이터가 정상적으로 수집되기 시작했습니다.

교훈

  • ILM 정책을 삭제하기 전에 해당 정책을 참조하는 인덱스가 있는지 반드시 확인해야 합니다.
  • 인덱스 템플릿의 우선순위(priority)를 적절히 설정하여 충돌을 방지해야 합니다.
  • ElasticSearch 클러스터 상태를 모니터링하는 알림 시스템을 구축하면 조기에 문제를 발견할 수 있습니다.
