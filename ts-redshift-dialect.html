Hibernate 6 이중 데이터소스(Redshift/RDS) 호환성 문제

2026.06
Hibernate 6 / Spring Boot 3 / QueryDSL / PostgreSQL / Redshift

배경

통계 조회는 기간에 따라 데이터소스가 나뉜다. 최근 2년 이내는 RDS(PostgreSQL), 2년 이전은 Redshift에서 조회하는 하이브리드 구조다. Spring Boot 3 / Hibernate 6 마이그레이션 이후 2년 이전(Redshift) 조회 경로에서 오류가 다발했다.

문제 1 · Redshift에서 페이지네이션 SQL 구문 오류

원인

  • Hibernate 6의 PostgreSQLDialect가 페이지네이션 SQL을 LIMIT ? OFFSET ? → OFFSET ? ROWS FETCH FIRST ? ROWS ONLY(SQL:2008 표준)로 변경
  • Redshift는 이 표준 구문을 지원하지 않아 구문 오류 발생

해결

  • Redshift용 Dialect의 getLimitHandler()를 오버라이드해 LIMIT/OFFSET 구문을 강제(LimitLimitHandler)
  • Hibernate 6의 기타 SQL 생성 변경사항(RETURNING, Sequence, FOR UPDATE, Array, DISTINCT ON 등)에 대해 Redshift 호환성을 전수 검토 후 영향 없음 확인

문제 2 · 잘못된 EntityManager로 엔티티 미인식

원인

  • Redshift를 쓰지 않는 일부 환경에서 2년 이전 조회 시 UnknownEntityException(예: r_stats_daily resolve 실패)
  • QueryDSL 팩토리 구성이 Redshift용 쿼리 팩토리를 만들면서 PostgreSQL용 EntityManager를 주입해, Redshift 전용 엔티티를 인식하지 못함

해결

해당 구성이 Redshift 전용 EntityManager를 사용하도록 교정.

문제 3 · 뷰 컬럼 누락으로 조회 불가

  • Redshift의 통계 뷰에 특정 컬럼(media_content_id)이 누락되어 2년 이전 데이터 조회가 실패
  • 뷰에 컬럼을 추가하고, 데이터 카탈로그의 union 대상 테이블을 전수 확인해 정합성 확보

교훈

  • ORM 마이그레이션은 생성되는 SQL 방언 자체가 바뀔 수 있다. 특히 PostgreSQL 호환을 표방하지만 표준 구문 지원이 다른 Redshift 같은 백엔드에서는 별도 검증이 필수다.
  • 멀티 데이터소스 환경에서는 각 소스에 맞는 Dialect와 EntityManager 매핑 정합성을 반드시 확인해야 한다.
  • 기간에 따른 데이터소스 분기처럼 평소 잘 안 타는 경로일수록 마이그레이션 회귀에서 놓치기 쉽다 — 경로별 스모크 테스트가 유효하다.
